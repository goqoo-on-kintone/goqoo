# 再設計セッション 2026-02-24

## 基本方針

### パッケージ分割
現在の「全部入り」構成を以下の3パッケージに分割する。

```
@goqoo/create        # scaffold（npx goqoo new）
@goqoo/vite-plugin   # ビルド設定（Viteプラグイン）
@goqoo/client        # ランタイムライブラリ（alerts / goqoo() / tools）
```

### ビルドツール
- webpack → **Vite** に移行
- 複数エントリポイントは `rollupOptions.input` で対応済み（Vite v3.2以降）
- React/VueはVite標準対応のため、goqoo側での同梱を廃止

### ダイアログライブラリ
- sweetalert（v1系・メンテ停止）→ **SweetAlert2** に移行
- `confirmDialog` / `successDialog` / `errorDialog` のAPIは維持
- 内部実装のみ書き直し

### goqoo() 関数の責務分離 ✅
- `goqoo()`本体は**二重実行防止のみ**に責務を絞る
- ビルド情報（COMMIT_HASH / BUILT_AT / NODE_ENV）の`window.__devinfo__`への埋め込みは
  `@goqoo/vite-plugin`側の責務に移管する
- これにより `@goqoo/client` がビルドツール非依存になる

## 追記：パッケージ構成の補足

### ginue / gyuma との関係
- ginue・gyumaは別リポジトリのまま（スコープ外）
- ただし `@goqoo/create` の scaffold 時に、インタラクティブな選択肢として提示する
  - 「ginueを使いますか？」
  - 「gyumaを使いますか？」
- 選択した場合のみインストールされる（現行のReact/Vue選択と同じUX）

### 移行方針
- 既存ユーザーへの移行パスは提供しない
- v2として破壊的変更を許容する

## 追記：generator系コマンドの扱い

### 廃止するもの
- `goqoo g app`
- `goqoo g customize-view`
- `goqoo g dts`

`g app` / `g customize-view` はAIが代替できるため廃止。
`g dts` はtrunks（スタンドアロンツール）と機能重複のため廃止。

### trunksの位置づけ
ginue・gyumaと同列に、`@goqoo/create` scaffold時の選択肢として追加する。

```
? Frontend Framework › None / React / Vue
? ginueを使いますか？ › Y/n
? gyumaを使いますか？ › Y/n
? trunksを使いますか？ › Y/n
```

### AIバイブコーディング対応
`g app`等のコードジェネレーターの役割をAIに委譲する方針とする。
scaffold時に `CLAUDE.md`（AIコンテキストファイル）を生成し、以下を記載する：

- プロジェクト構造の説明（`src/apps/`配下の規約など）
- `goqoo()`関数の使い方と意図
- kintoneイベントの書き方パターン
- `@goqoo/client` のダイアログAPIの使い方

「コードを生成する」から「AIがコードを生成できるようコンテキストを提供する」への役割転換。
